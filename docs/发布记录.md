### 修复内容

修复 v1.0.7 后用户实测发现的三个问题：

**问题 1：首页选皮肤进游戏后皮肤不生效**
- **根因**：`view.applySkin(skinId)` 把 `skinId` 传给了球杆，但桌台重新着色读的是带内存缓存的 `Settings.get().skin`——缓存里仍是加载时的旧值，结果只有球杆变色，桌布 / 库边维持上一次。同时桌台颜色此前只在 `assets/wave.jpg` 异步贴图回调里设置，但该贴图实际不存在（fork 上游遗留），回调不执行。
- **修复**：`applySkin` 透传 `skinId` 给桌台 `recolorTable`；桌台同步上色提到模型加载阶段；抽出 `paintTable()` 让首次加载与实时换肤共用同一套着色逻辑。

**问题 2：被击球辅助线任何角度都不出现**
- **根因**：限制条件写死为「仅第一人称」而默认进入游戏就是俯视；`Overlap.getFirst` 阈值过严，只在准星几乎正对球时才识别；并且 `three-utils.norm()` 共享一个 Vector3，连用两次会互相覆盖，导致袋口点积永远是 1。
- **修复**：移除第一人称限制；改用专属临时向量自管 normalization；找不到目标球时回退到画白球自身走向，任意角度都有线。

**问题 3：俯视图点击非白球无法自动对准**
- **根因**：`onPointerDown` 类字段被右键版本覆盖，左键查球的逻辑根本没接上。
- **修复**：合并成一条 `onPointerDown`，左键就近查球（半径 2.2 R）并触发 `onBallTap`。

**问题 4：调试句柄污染**
- `globalThis.__bc` 改为 `?debug=1` 才挂载，不污染正式包。

## v1.0.3



发布时间：2026 年 8 月 3 日

### 修复内容

修复**开始游戏后界面全黑、没有任何 3D 场景**的问题。

**根因**：three.js 的 `FileLoader` 使用 `fetch()` 加载 `.gltf`、`.bin`、纹理和音效文件；Android WebView 在 `file://` 页面中直接拒绝任何 `file://` 请求的 fetch，错误为 `URL scheme file is not supported`。这导致桌台模型和贴图全部加载失败，3D 场景为空，玩家只看到黑色背景（而主菜单是内联 HTML，所以能正常显示）。

**解法**：不再使用 `file:///android_asset/`，改为让 WebView 加载虚拟 https 域名 `https://billiards.local/`，并通过 `WebViewClient.shouldInterceptRequest()` 在本地把所有请求映射回 APK 内的 `assets/dist`。页面 origin 变成正常的 https，fetch 完全可用；同时不创建任何真实网络连接，依旧零权限、纯离线。

**改动**：

- `MainActivity.java`：重写 `shouldInterceptRequest()`，实现本地资产拦截器；加载入口改为 `https://billiards.local/menu.html`
- `MainActivity.java`：继续强制硬件加速，并通过反射尝试开启 `setAllowFileAccessFromFileURLs` / `setAllowUniversalAccessFromFileURLs` / `setMediaPlaybackRequiresUserGesture`
- `webgl.ts`：新增诊断浮层。若 WebGL 上下文创建失败，会在屏幕上显示明确错误原因，避免纯黑屏
- `menu.html` / `menu-cn.js`：在「关于」页增加开发者 **huang336** 信息，并修复版本号重复显示
- `versionCode` `26080402` → `26080403`
- `versionName` `1.0.2` → `1.0.3`

## v1.0.2

发布时间：2026 年 8 月 3 日

### 修复内容

修复 **Android 11 及以上全系机型**的安装失败。v1.0.0 与 v1.0.1 均无法安装，已在 GitHub 上标注废弃。

**根因**：组包时 `zip -qr` 把 `resources.arsc` 一并压缩了。

自 Android 11（API 30）起，系统强制要求 APK 内的 `resources.arsc` 以 **STORED（不压缩）** 方式存放且 4 字节对齐，否则包管理器拒绝解析，返回 `INSTALL_PARSE_FAILED_RESOURCES_ARSC_COMPRESSED`，其数值正是 **-124**。小米澎湃 OS 把这类错误统一显示成「该安装包与您的系统不兼容」，极易被误判为系统版本问题。

`zipalign` 只负责对齐、不会解压，所以补跑对齐救不回来 —— 必须在组包阶段就把 `resources.arsc` 单独以 store 方式写入。

**改动**：

- 组包流程：其余文件正常压缩，`resources.arsc` 用 `zip -Z store` 单独追加
- `build-apk.sh` 增加出厂校验，`resources.arsc` 压缩方式或对齐不合格则构建直接失败并退出，杜绝再次分发坏包
- `build-apk.sh` 补上 d8 输出目录的 `mkdir`
- `versionCode` `26080401` → `26080402`
